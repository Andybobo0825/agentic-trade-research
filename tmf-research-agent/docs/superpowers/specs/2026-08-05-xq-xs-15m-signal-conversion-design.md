# XQ XS 15 分鐘訊號轉換設計

**日期：** 2026-08-05  
**狀態：** 已核准方向，待實作  
**來源：** `../pine/taiwan-mtf-bb-sr.pine`、`../pine/taiwan-mtf-bb-sr-strategy.pine`

## 1. 目標

新增兩份可貼入 XQ 全球贏家 XS 編輯器的研究腳本，固定用於 MXF 15 分鐘 K：

1. 指標版：顯示布林通道、已確認支撐壓力與四種訊號。
2. 策略訊號版：以本機狀態模擬單一虛擬部位、下一根開盤進場、持有 16 根及時段結束出場。

原始 Pine 檔必須維持位元級不變。XS 腳本不得送單、不得查詢帳務或真實持倉，也不得包含任何可轉送委託的程式路徑。

## 2. 新增檔案

- `xq/taiwan-mtf-bb-sr-15m.xs`
  - XQ 技術指標腳本。
  - 計算並繪製布林中軌、上軌、下軌、最新確認壓力與最新確認支撐。
  - 輸出帶量突破、帶量跌破、支撐止跌、壓力遇阻四種訊號。
- `xq/taiwan-mtf-bb-sr-strategy-15m.xs`
  - XQ 研究／訊號腳本，不是交易腳本。
  - 預設啟用帶量突破做多與帶量跌破做空；另外兩種訊號保留輸入開關。
  - 使用自有變數模擬 `FLAT`、`LONG`、`SHORT`，只輸出進出場訊號與虛擬部位，不呼叫交易函數。
- `tests/test_xq_xs_scripts.py`
  - 鎖定來源 Pine SHA-256。
  - 驗證兩份 XS 均固定拒絕非 15 分鐘圖表。
  - 驗證核心參數、四種訊號、虛擬持倉與出場規則存在。
  - 驗證不存在 `SetPosition`、`Position`、`Filled`、委託、帳務、憑證與券商 API 字樣。

## 3. 固定參數與適用範圍

兩份腳本都固定採用目前 Pine 的 15 分鐘自動參數：

| 項目 | 值 |
| --- | ---: |
| 布林期數 | 20 |
| 布林標準差倍數 | 2.0 |
| Pivot 左右確認根數 | 4 |
| 支撐壓力容許區 | 0.20% |
| 成交量均量期數 | 20 |
| 放量倍數 | 1.6 |
| 固定持有根數 | 16 |
| 同時虛擬部位 | 最多 1 口 |
| 日盤出場截止 | 13:30 |
| 夜盤出場截止 | 04:45 |

腳本開頭必須檢查 `BarFreq = "Min"` 且 `BarInterval = 15`。不符合時不產生任何訊號，避免把 15 分鐘參數誤套到其他週期。

## 4. 指標等價規則

### 4.1 布林通道

XS 使用 `Average(Close, 20)` 作為中軌，搭配母體標準差計算上下軌：

```text
middle = Average(Close, 20)
deviation = StandardDev(Close, 20, 1) * 2.0
upper = middle + deviation
lower = middle - deviation
```

### 4.2 Pivot 支撐壓力

Pine 的 `ta.pivothigh(4, 4)`／`ta.pivotlow(4, 4)` 會在右側四根完成後確認中央候選 K。XS 以固定迴圈檢查最近九根：

- 候選值位於 `High[4]`／`Low[4]`。
- 候選高點不得低於左右各四根高點。
- 候選低點不得高於左右各四根低點。
- 確認後更新最新壓力／支撐。
- 當根訊號使用更新前的上一根已確認值，避免新 Pivot 回頭改變同根訊號基準。

若相同價格並列，採 Pine 的寬鬆比較語意，允許候選點成立。

### 4.3 成交量

```text
averageVolume = Average(Volume, 20)
strongVolume = averageVolume > 0 and Volume >= averageVolume * 1.6
```

### 4.4 四種訊號

1. 帶量突破：收盤由下往上穿越前一根已確認壓力、放量、收盤高於布林中軌。
2. 帶量跌破：收盤由上往下穿越前一根已確認支撐、放量、收盤低於布林中軌。
3. 支撐止跌：K 棒碰觸支撐 ±0.20% 區域、最低價碰到布林下軌、收盤不低於支撐且收紅。
4. 壓力遇阻：K 棒碰觸壓力 ±0.20% 區域、最高價碰到布林上軌、收盤不高於壓力且收黑。

所有判斷只在 15 分 K 收盤完成後成立，不使用盤中尚未完成資料。XS 以
`not IsLastBar` 排除仍會隨即時成交改變的最新 K；下一根出現後，前一根才
進入 Pivot 更新與訊號判斷。

## 5. 虛擬策略狀態機

策略訊號版不使用 XQ 交易函數，而以三態整數模擬：

```text
0 = FLAT
1 = LONG
-1 = SHORT
```

### 5.1 訊號優先序

- 空手時才能接受新訊號。
- 預設多方條件為「帶量突破」，預設空方條件為「帶量跌破」。
- 若同一根同時出現多空訊號，視為衝突，不建立虛擬部位。
- 不加碼、不攤平、不直接反手。

### 5.2 下一根開盤進場

Pine 原策略在訊號 K 收盤成立後，下一根開盤成交。XS 以 `pendingDirection` 保存訊號，並在下一根已完成 K 的計算開始時：

- 將虛擬進場價記為該根 `Open`。
- 將虛擬部位切換為 `LONG` 或 `SHORT`。
- 輸出一次進場脈衝。
- 記錄進場 bar 序號，讓持有根數從實際虛擬成交 K 起算。

### 5.3 出場

- 虛擬部位持有滿 16 根時輸出持有到期出場。
- 日盤時間達 13:30、夜盤時間達 04:45 時輸出時段出場。
- 時段出場優先於新進場；出場同根不得反手。
- 停損與停利不納入此版，因目前回測基準未啟用，避免擴大未核准行為。

## 6. XQ 顯示輸出

因 XQ 與 TradingView 圖形 API 不等價，本次只移植可驗證的研究輸出：

- 指標版使用 `Plot1` 至 `Plot5` 顯示布林三軌與最新支撐壓力。
- 以額外 Plot 輸出四種訊號脈衝，讓使用者可在 XQ 圖表設定顏色與標記。
- 策略訊號版輸出 `LONG_ENTRY`、`SHORT_ENTRY`、`EXIT`、`VIRTUAL_POSITION` 數值序列。
- 不移植 Pine 的 table dashboard、動態 label、line 物件與 barcolor 外觀；這些只屬 UI，不影響訊號計算。

## 7. 安全邊界

XS 檔案不得包含或使用：

- `SetPosition`
- 真實 `Position`／`Filled`
- 市價、限價或委託函數
- 帳號、持倉、成交、保證金查詢
- 憑證、登入、券商 API 或網路呼叫

檔頭必須標示「研究訊號、禁止送單」。測試會把上述邊界當成失敗條件。

## 8. 驗證方式與限制

### 自動驗證

1. 先執行專案唯讀驗證器。
2. 執行新增的 XS 靜態契約測試。
3. 執行既有完整測試套件。
4. 重算兩份 Pine SHA-256，確認與實作前完全相同。

### XQ 編譯限制

本機沒有 XQ XS 編譯器，因此自動測試只能驗證結構、公式、禁用能力與來源完整性。最終語法編譯仍須以 XQ 全球贏家 XS 編輯器為準；若編譯器回報版本差異，只能新增修正版 XS 檔或修改新建 XS 檔，原 Pine 仍不得改動。
